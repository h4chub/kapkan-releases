# KapKan Client companion

Release 1.0.5 has separately compiled Minecraft 26.1, 26.1.1 and 26.1.2 builds, each requiring Fabric Loader 0.19.5+ and Java 25. Three matching Fabric API modules are nested in each build; a separate full Fabric API installation is not required. Compile all targets with `python3 companion/build.py` from the repository root. Run target-specific deterministic tests with `python3 companion/test.py --minecraft 26.1.2` and audit the build set with `python3 companion/check_compatibility.py`. Use JDK 25 in PATH or set `KAPKAN_JDK`. See [COMPATIBILITY.md](COMPATIBILITY.md) for exact build and unsupported-version scope.

The existing badge engine remains separate from cosmetic settings. New preferences are in `~/.kapkan/client.properties`; capes and skins are local PNGs in sibling directories. Imported files are bounded, decoded only on selection/import, normalized and copied. Textures are cached; the renderer receives an immutable cape frame. `SharedCapes` renders validated remote cape images from the server relay, or from an explicitly configured protocol-2 HTTP service, with separate motion per player and a bounded image/texture cache. Network PNG validation and native pixel decoding run on bounded worker queues. GPU texture registration and disposal run on the client thread. The HTTP endpoint is unset by default; imported skins remain local. See [COSMETIC-SYNC.md](COSMETIC-SYNC.md) for installation, identity, visibility and limits.

`CapeMotion` uses a fixed 20 Hz update with four constraint substeps, damped velocities, gravity and movement-driven wind. Idle time supplies no continuing wind. Render interpolation is independent of frame rate. The renderer respects invisibility, spectator state, the vanilla cape flag, swimming and wing equipment. It follows the animated torso attachment.

The menu uses native Minecraft Screen/widgets/input/narration with display-resolution, anti-aliased shapes and bundled Inter typography (SIL OFL included). DejaVu remains available for Minecraft-native narration/fallback components. White alpha textures are linearly sampled and tinted by the GPU; a bounded cache avoids per-frame rasterization and excludes tint/opacity from texture identity. Its 3D preview explicitly scales picture-in-picture bounds because that API does not inherit the GUI pose stack. It includes selectable premades, an editable studio, PNG import, skin model selection, the explicit No Kapkan Cape selection, HUD controls and zoom. Key registration occurs before options loading. J is the default menu shortcut and uses Minecraft's native rebindable controls.

QA drivers under `qa/` launch the actual game with an isolated test-only mod. They are never included in the production JAR. See the root QA report for results and limitations.

The following describes the preserved earlier cosmetic pipeline. Build 8 replaced the stock textile patterns with Black, Ivory and Burgundy logo capes at 320 × 512. Settings are grouped into Display, Controls and Cape motion. Studio is reached through Capes → Customize. MenuInput retains the native EditBox state, including selection and IME composition through a read-only accessor.

Build 9 adds the colour-preserving, depth-tested cape pipeline, a bright normal-layer name badge, the importer catalogue link, and optional protocol-2 sharing. See the root QA report and `presence-service/README.md` for the tested scope and hosting setup.
